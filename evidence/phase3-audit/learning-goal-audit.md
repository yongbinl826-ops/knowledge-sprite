# 学习目标与项目迁移要求独立审计

本次只读审阅 r9c 留存的5例31单元及19个无本课正文/目录支持的路线。未发HTTP/模型、未连接数据库、未改生产源码或测试。原31/19、13 API some/18 none、12正文some/19 none等历史指标保留，未追认为通过。

## 主要判断

单元通常有明确子任务，整体不需要普遍细拆。主要问题是把可迁移技能、实现默认和项目验收混入相同concepts及覆盖分母，进而要求来源展示相同参数/业务。19缺口的规范性主要分类为：

|分类|数量|处理|
|---|---:|---|
|连贯技能块|9|保持单元粒度，找具体方法；不要求同项目，不退回泛入门|
|同单元双教学切面|5|允许两份针对性材料组合，仍产出一个项目成果|
|跨单元集成练习|5|复用先修，项目业务规则独立验收；有真缺项再补资料|

这是设计诊断分布，不是搜索失败的因果归因。19缺口中3个已有局部卡（时间解析API、CSV输出、随机数），16个没有展示局部卡；后者仍可能是检索/观测不足。不能仅由0卡证明无视频，也不能只改目标文字就宣布通过。

## 两类要求分别保留

视频学的是可迁移方法，例如日期解析/布尔筛选、网格移动校验、非阻塞计时、稳定去抖、控件值到筛选、加权比率。不同数据集/地图大小/按键/状态名可以教同一技能。项目中仍必须按原要求做出结果：end==start保留、0分钟有效、8×8不能穿墙、胜利后事件活着、专注计数/暂停政策、低有效按钮与稳定去抖、空房间无结果、加权而非逐行均值等均不删除。

不能全局移除数字/比较/API边界校验。应改变所校验声明的对象：对教学材料只声称实际教过的技能与语义；对学生项目仍精确检验原参数和边界。标题层相关性与正文/目录讲授范围分开标注，不从标题/搜索摘要编造参数、章节或算法。真实视频身份和同源绑定继续保留。

## 31单元共同的数据流问题

现模型已区分project_task与practice_check，但concepts仍把文件名、计数链、业务条件等混作技能。project_search将concepts原样传为learning_targets，ranking又将标题拆项/操作核心与全部concept加入覆盖分母。31单元均有这两层并计，不能机械认定每一行都重复；明确例子包括时间解析的多层重叠及Flex标题与同技能概念。后续应为非重复技能建映射，项目约束另保留。

四个具体多工具/已知技能例子：Matplotlib单元含pandas聚合；CSS单元含HTML原生按钮行为；Streamlit上传/图表单元含学生已有的pandas能力。技术应随技能归属，不应要求一个CSS视频同时证明HTML行为，也不应让已会groupby的学生重学整套pandas。

先修也需区分知识依赖与执行顺序：小时分组不必先算时长，CSV导出不必先画图；网格合法移动可先纯函数测试、按键事件独立学；去抖用millis时应先给时间差短说明；未上传/空数据保护应从最小页面存在。

## 三个未见项目（仅事前规划）

### 离线复习卡网页 / beginner

会基础 HTML/CSS、JavaScript 变量、if、数组与简单函数；第一次将 DOM 事件与本地保存组成应用。

使用原生 HTML/CSS/JavaScript 展示12张合成术语复习卡。上一张/下一张切换，首尾禁用对应按钮；可标记已掌握，显示已掌握数量。刷新后从 localStorage 恢复标记，首次打开无数据或本地数据损坏时给提示并安全恢复默认。手机可用，原生按钮可键盘操作。不登录、不联网、不做推荐算法、云同步或后端。

技能检索：JavaScript · 数组索引与 DOM 状态渲染；JavaScript · 事件监听、原生按钮 disabled 与状态更新；JavaScript · localStorage JSON 存取与损坏/缺失数据处理。

拒绝：只有 JS 变量/循环基础替代存储/DOM 技能；React/Vue/后端数据库课程当原生 localStorage 教学；仅相同复习卡标题但没有对应方法证据。

同方法的不同项目来源可以迁移；12张卡、术语内容、按钮文案与计数显示格式留在项目练习，不要求视频同值。

### pygame 双人乒乓球 / intermediate

会 Python 函数/列表和 pygame 窗口、绘图、离散按键事件；未做持续输入、速度运动、反弹和一局多轮状态。

用 pygame 做本地双人乒乓球。W/S控制左拍、上下键控制右拍，按住可持续移动且球拍不出屏；球按经过时间移动，碰上下边界或球拍反弹。出左右边界给另一方加1分，显示比分并暂停等空格发球，先到3分显示获胜；获胜后R重开，Esc/关窗始终可退出。固定单屏，不做AI、联网、音效或物理引擎。

技能检索：pygame · 持续键盘状态与对象边界限制；pygame · 基于经过时间的速度运动；pygame · 球与边界/球拍碰撞后的方向反射；pygame · 轮次状态、得分与持续事件循环。

拒绝：Python基础整课代替 pygame 运动/碰撞；KEYDOWN一次移动当持续输入已满足；clock.tick限帧当真实时间位移已证明；同名Pong项目只有效果演示/未解释方法就声称教全。

同方法的不同项目来源可以迁移；W/S与方向键、3分阈值、空格/R键、场地尺寸与颜色留在项目练习，不要求视频同值。

### Arduino 电位器调节 LED 亮度 / beginner

会上传程序、做过LED点亮；第一次使用模拟输入、PWM和数值范围映射。

用Arduino Uno、电位器、带限流电阻的LED做低压亮度调节器。读取电位器位置并映射为LED亮度，转到两端分别接近最暗/最亮，中间位置为中间亮度；串口显示原始读数和输出值。约每50ms采样一次，主循环不长时间阻塞，越界输入被限制在有效输出范围。断电接线、共地和LED极性必须说明，模拟输入电压及PWM引脚先按板卡官方说明确认。不连接市电、电机、继电器，不加按钮、传感器联网或屏幕。

技能检索：Arduino · 电位器模拟输入接线与 analogRead 观察；Arduino · 输入范围到PWM输出的映射与限幅；Arduino · 非阻塞周期采样和串口调试。

拒绝：digitalWrite闪烁课替代PWM亮度控制；纯Python输入输出、其他不兼容板卡引脚示例；只含analogRead/analogWrite符号清单或无讲解演示；元件额定值/输出范围未核对却承诺硬件安全。

同方法的不同项目来源可以迁移；50ms周期、元件/引脚选型与串口格式；源材料不要求相同数值留在项目练习，不要求视频同值。

## 实施建议与验证边界

保留单元及全部需求/默认假设，增加独立技能与集成练习角色、每技能工具及学生已会状态。先建立需求→技能→项目练习映射，再让检索围绕新缺项技能，在原有预算内找资料。技能材料可用性、证据深度、学生项目完成度分开呈现，不再用材料是否展示相同项目来决定相关性。

本轮只提供原因审计与方案，等待根线程分工实施。三新例尚未调用模型或搜索；没有执行学生代码/看板/硬件，也没有外网部署。旧失败/成本账不改写；后续需要新版契约兼容、对照正反例和有界真实复测才能评价改进。
