# r10 前端学习支持与项目实践合同审计

结论：**当前分母确实混合了可迁移技能、精确参数语义、项目迁移条件和验收要求。它衡量的是“原项目要求有多少得到同课正文／目录逐项支持”，不宜直接表示“视频有没有学习价值”或学生学习完成度。** 这属于产品指标和目标分类问题，不能通过放宽来源校验来修。

本审计只读源码和已保存的r9c证据，0网络／浏览器／模型／搜索／数据库读写。未改源码、测试、dist或旧验收文档，49个冻结文件前后均无SHA漂移。实现尚未开始，等待父任务分配归属。机器可读证据、精确源SHA与行号在`frontend-contract-audit.json`。

## 现有证据能说明什么

旧口径仍是31单元、12个有自身正文／目录支持、19个无此支持、0full。**19个零支持单元中，16个没有任何材料，只有3个已有partial卡。** 不能把19个全部解释成“分母太严”，更不能靠重分类让空结果变成合格。

三条有材料但零清单支持的路线是：

| 现有单元 | 材料与当前展示 | 审计解释 |
| --- | --- | --- |
| Data k3 时间解析与无效行分离 | 1张to_datetime使用核心partial，0/8 | 确有自身视频标题的API入门线索；没有正文／目录或参数教学证明。能提示学生核对入门材料，不能填满errors、筛选、end&lt;start或相等边界 |
| Arduino k4 随机等待与计时 | 1张random使用核心partial，0/5 | 有随机数入门线索；random参数、millis、非阻塞仍是实际学习缺口。项目选取的等待时长与验收样本应放到迁移练习 |
| Data k7 CSV输出与日志 | 1张CSV相关partial，0/9 | 已确认视频页面身份与相关标题，但当前支持ID是search记录；英文目录未被现有解析器确认。保持标题线索与正文／目录两个合同，不伪换目录ID |

数量也需校正：冻结结果实际有**5个API核心单元**，分别为Data k2／k3、Arduino k2／k4、Dashboard k1，不是3个。另3个已有其他正文／目录技能支持，分别显示1/6去重、1/6串口调试、2/5上传及脚本重运行。三条零清单且有材料的路线则是“两条API核心＋一条CSV标题层”。全部5条API核心的支持记录均为自身`page/title`，**不能仅凭它们说课程已完整教授该技能、参数或项目行为**。

## 为什么会这样

1. `LearningCoverage.tsx:189–211`把所有confirmed concepts、标题拆分、`operation_core`和`operation_qualification`放进一个列表。concepts只是字符串，没有“技能／参数语义／迁移／验收”角色。代码没有直接把`practice_check`字段加入分母，但同类实践要求已经混进concepts和标题限定中，如文件名约定、min值校验、具体随机范围、项目状态名。
2. `LearningCoverage.tsx:200–207`只接受collection目标的精确ID和文字，因此match-only `api_operation_core_*`会被过滤。这正确保护了原参数与业务要求，却使路线无法表达补充材料的有限入门价值；它只在较长的卡片理由中出现。
3. `topicEvidence.ts:17–28`允许search／page／catalog作为卡片相关性依据；LearningCoverage另有更强的自身正文／目录与绑定摘要校验。这两层本来不同，但“部分匹配／已有来源证据”与“视频可支持0/N”缺少近邻解释。r9的“这些学习目标尚无足够……”已经更精确，仍不足以解释不同证据层。
4. `LearningCoverage.tsx:223`对所有missing项都提示继续找视频或资料。学生已学会字体渲染后，可能应把它用于WIN提示；“必须再找一个使用相同状态变量名的教程”并非合理要求。反过来，真正缺状态机、布尔逻辑或参数语义时，仍必须补学。
5. whole_topic、标题片段、操作核心、业务限定和细concept同权扁平计数，粗细重叠。`coverageDisplay.ts:19–49`只按完全同文保守合并并保留全部ID，机制本身没有失效；它不能解决教育角色未分类的问题。未来分轴后，同文合并也必须局限在同一轴，不能让未尝试的项目练习抹掉已证实的技能支持。

旧0full在旧合同下仍是事实；它不能推出“31单元没有任何可用教学”，也不能在换口径后倒改为“生产已通过”。真正无材料、无参数教学与来源身份未确认的问题仍须保留。

## 建议的清晰UI合同

主路线分为两部分，继续使用现有白／石墨／蓝与细线层级，不增加问卷或大仪表盘：

**先学这些技能。** 列出有自身简介／目录／绑定课程正文支持的可迁移技能；必要的参数语义也可以是技能，例如errors的含义或随机函数边界。另设轻量的“入门线索”行，保留自身标题明确提到的原API／概念用法，但标明“教学内容与参数仍待核对”。搜索标题层再明确标“相关标题线索”，不能混入正文支持数。

**带回项目练习。** 保留本项目字段、选定常量、规则、输出与验收条件，默认“待自己实践”。材料命中不自动完成练习；练习也不因没在教程出现相同变量名或数值而使一个已证实的通用技能失去支持。项目验收由学生试做／检查独立记录，不能由搜索或模型自动宣布通过。

分母必须先有稳定分类。不能在前端用正则删除参数、数字、别名或业务词来“制造通用技能”，也不能把所有具体要求都搬到练习以提高分数。混合条目需上游明确拆分，并保留原ID与原文映射。例如：

| 原要求 | 学习支持轴 | 迁移／实践轴 |
| --- | --- | --- |
| pd.to_datetime(errors)、end&lt;start、相等边界 | API用途、errors语义、缺失／布尔筛选；各自需来源依据 | 按本项目规则分离无效行，并用相等时间样本检验 |
| random(2000,5001)、millis、非阻塞 | 随机数用途、参数边界、真实时间差与非阻塞控制是不同技能；不能互相代证 | 设置项目要求的等待时长，并实测响应与范围 |
| pygame.font渲染、READY／PLAYING／WIN | TWT正文可支持字体渲染；状态机与状态渲染关联仍另需教学 | 用本项目状态组织显示，不要求教程使用同样变量名 |
| DataFrame.to_csv(index=False)、文件名与输出检查 | CSV写出及必要参数语义待确认；当前只有标题线索 | 输出本项目两个文件、检查命名／目录／日志 |

### 来源层级与措辞

| 证据 | 可用措辞 | 是否计为内容支持 |
| --- | --- | --- |
| 自身正文／目录或严格绑定的视频摘要 | “简介／目录支持：字体渲染” | 是，仍不代表完整教学、播放或学会 |
| 自身标题明确API／概念用法＋已确认视频身份 | “入门线索：random用法；参数与教学内容待核对” | 否，单独展示线索 |
| 搜索标题相关，即使视频身份另已确认 | “相关标题线索：CSV读写；正文／目录待确认” | 否，不替换原支持ID |
| 身份或内容待核实 | “待核实材料” | 否，不借其填技能或参数 |

分类落地前，建议暂不创造新的“技能X/Y”。把旧0/N放进可展开的“原项目要求来源核对”明细，主视图优先展示技能清单、明确弱证据的入门线索与独立项目练习。分类确认后若保留技能X/Y，只统计已分类的技能／参数语义目标，分类未知不可静默丢掉。

下一步也按原因区分：有技能内容就先学再试做；只有标题线索就先核对该课简介／目录及参数资料；真正缺技能材料才引导补搜；没有任何材料时继续明确空结果与重试。不能一律要求再找覆盖所有项目细节的视频。

## 现有样本应如何表达

- Data k2：明确“已有去重技能内容；另有drop_duplicates入门线索”；subset／keep与删除统计规则仍未知，不把API原词提升成完整参数覆盖。
- Data k3：显示to_datetime入门线索，保留errors、isna、比较与边界缺项；原0/8仍可在原要求核对中追溯，不描述为“视频没有任何价值”。
- Arduino k2：串口调试的内容支持保留；input_pullup另列原词线索，不凭词形推断函数签名、pinMode等价或按下LOW。
- Arduino k4：random线索可核对；范围参数、millis与非阻塞仍待学；项目具体等待时长与试验属于迁移练习。
- Dashboard k1：上传和脚本重运行的真实内容支持保留；file_uploader线索不能自动证明精确st.file_uploader、pandas读取和未上传分支。先学已有内容，再补接口用法与项目接线。
- CSV k7：保持相关标题与内容证据分层，不改0/9或伪造英文目录支持；把输出文件名、路径和日志安排到实践清单。
- Maze k4：可迁移的字体技能明确可学；WIN状态提示作为迁移任务，状态机本身仍是知识缺口。r9c已去掉只有“显示文字”标题却冒充精确API的B站误配，不能重新放宽。
- Web倒计时等16条无材料路线：即使拆开项目验收，仍没有现有课程可推荐；必须保持真实缺口，不能由UI重排变成成功。

## 交接建议与后续验收

先由父任务决定展示与上游目标分类的文件归属。最小一步可先分层显示现有技能／线索／实践，并把旧计数降为明细，不改来源合同或虚构新分母。随后增加显式目标角色与原ID映射，再审阅可迁移技能的覆盖。

未来回归应证明：技能有内容支持时不被尚未实践的项目条件抹掉；5个API核心仍只是标题线索、不加正文支持；参数、别名、业务边界不被代证；CSV不伪换ID；16条空材料保持缺口；平台／版本／上限、待核实、scope失配与来源哈希防线保持；同文不能跨学习／实践轴借用状态。所有用例仅是建议，本审计没有运行新测试。

本阶段交付的是原因和合同方案，**不是已实现的新UI，也不是重新宣布生产验收通过**。保持r9c预览与所有旧证据不变，等待实现归属。
