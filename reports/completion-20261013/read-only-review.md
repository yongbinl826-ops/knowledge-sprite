# 冻结后的只读交付审查

日期：2026-10-13。审查对象为当前 `.env.example`、README、API 合约、`scripts/live_completion_acceptance.py`、身份/生命周期报告及对应源码。仅阅读文件并记录 SHA-256；未发出外网请求，未访问正式 SQLite，未执行验收脚本、测试或重启服务。本次唯一新增文件是本报告。正在进行的真实验收结果不由本报告推定。

## 结论

未发现当前准入、排序及展示流程把普通 Course 结构直接当作视频或已播放的实质问题。当前身份摘要按默认与平台视图实际返回资源的并集统计，未声称全球独立课程数。当前版本页面缓存已剥离查询特有的搜索回退文本，规则及 LLM 的相关性文本按知识点隔离。

交付中仍需澄清两处新验收脚本的计数/通过口径，以及几处文档差异。它们不要求重跑真实请求；可保留原始报告，另行读取保存的证据作严格核验，或在最终说明中限定指标含义。以下行号为本次读取快照。

## 发现与最小建议

### R1：新脚本的“展示目录行数”没有通过展示所用的逐行证据校验（中）

位置：`scripts/live_completion_acceptance.py:101–115`，尤其第 115 行。

`displayed_catalog_rows` 直接对资源的 `chapters` 求长度；前端 `ResourceCard.tsx:41–59` 则要求本章 ID、`chapters.N`、合法来源 URL、JSON 中五个字段和有限合法时间全部一致，才显示该行。因此原始章节行数可能大于实际可展示、已核验目录行数；原始列表非空不能作为目录验收通过证据。脚本还按 resource ID 跨任务取最后一份资源，故该数也不是全部任务章节观察的总和。

最小建议：原指标明确称 `raw_catalog_rows`，最终报告独立给出严格核验行数及其计数集合；可对已保存的 `{resource, evidence}` 使用既有 `scripts/live_acceptance_revision.py:104–162` 中逐章校验逻辑离线计算，保留原始记录，不重新联网。视频目录还须独立核验 `video_evidence_status` 和 `catalog_kind`，普通课程大纲不计为视频目录。

### R2：`completed_cases` 与退出码表达运行收集结束，不能单独表达验收通过（中）

位置：`scripts/live_completion_acceptance.py:17,79–84,107,119,123`。

`final_job` 在 completed、partial、failed、interrupted、cancelled 任一终态都会保存；第 107 行的 `completed_cases` 数的是这些终态任务总数。退出码 0 只表示没有被捕获的脚本/HTTP 异常：任务失败、结果为空、没有目录，以及 `source_unchanged_during_run=false`，本身都不触发非零退出码。这不等于应把部分或零结果改为失败重跑，而是“运行完成”和“实际观察满足哪些目标”必须分开。

最小建议：最终报告把该字段解释为终态任务数，分别列出各状态、实际资源/课程/视频/目录证据及未满足项；不要把 exit 0 写成“全部真实验收通过”。若保留自动验收名称，应单独输出有明确判据的检查结果，不以进程退出码代替。

相关边界：脚本第 54–56 行校验并发与搜索/详情预算，但没有校验任务实际 `budgets.deadline_seconds` 是否为冻结计划的 240；第 81 行只是客户端轮询等待上限。最终报告应以每个保存任务的预算为准。第 24–28 行的前后哈希覆盖应用源码和锁文件，未覆盖脚本本身及冻结输入；本报告在下方补记这两份文件的哈希，不能把原字段解读成所有运行材料均受其检测。

### R3：示例配置的路由注释已过时（低）

位置：`.env.example:6`。

该注释称 course/site 查询仍走 general；实际 `backend/app/providers.py:249–252` 只根据查询中的视频意图及视频引擎配置选择路由，不因 site/domain 限定排除视频索引。README 第 63 行已经正确说明“包含站点限定查询”。

最小建议：只改注释为“含视频意图的查询使用视频引擎，包含站点限定查询；其他查询使用一般网页引擎”。无需改行为。

### R4：API/README 未完整列出本轮可靠页面课程准入和身份字段（低）

位置：`docs/api-contract.md:17,19`、`README.md:109`；对应 `backend/app/service.py:684–708` 与 `backend/app/ranking.py:102–132`。

当前还允许有独立、同来源页面凭据的可靠 Course，即使没有视频证据；其 `video_evidence_status` 仍为 none，前端显示“页面含课程结构证据 · 是否含视频未核验”。文档只列了视频候选与平台搜索课程入口，容易漏读这一合法课程分支。API 响应示意也未列出 `identity_summary`、`course_identity`、`parent_course_url`、`resolved_url`。

另外，API 所称“全平台/每平台前 5 项”实际先按已有分数排序，再优先分散已识别课程家族、最后补齐同家族条目；它不是严格的分数前五。身份报告第 45–54 行已准确说明。

最小建议：在现有条目后补充可靠页面 Course 分支（视频仍未知）、新增身份字段及来源范围，并把“前 5 项”改为“按排序与课程家族分散策略最多返回 5 项”。无需调整当前算法。

### R5：排队即取消的任务不保证包含采集诊断（低）

位置：`README.md:155`。

“完成/取消后的任务详情包含 fetch_diagnostics”略强；排队阶段取消不会执行 `run` 的诊断收尾，API 第 35 行和生命周期报告已明确该字段可能不存在。

最小建议：改为“实际执行后结束或取消的任务详情可包含”，并补一句排队未执行可能无字段。

### R6：界面身份统计是所有返回视图的并集，不随当前筛选变化（说明性）

位置：`frontend/src/components/ResultsPanel.tsx:37–40`、`backend/app/service.py:701–708`。

实现与身份报告一致：摘要按默认项和各平台项并集、resource ID 去重。切换平台或类型后，摘要不重新计算。因此“已返回 N 条资源”可以多于当前屏幕卡片数；当前也没有称其为当前视图数或独立课程数，不属于计数算法错误。

最小建议：最终说明明确这是“本任务全部已返回视图的并集”；后续若改提示文字，可加入“含平台筛选结果”，无需变更计数或增加检索。

## 专项核对与保留边界

### Course、视频结构、目录和播放

- `ranking.has_course_page` 要求实际页面成功、独立类型凭据、可信类型来源和相符页面 URL；`has_learning_evidence` 将它与搜索课程入口、视频依据作为不同准入分支。
- `ResourceCard.tsx:74–85` 将普通页面 Course 与视频结构分开；两者均明确不等于观看验证，登录、付费、选课和可播放性未知仍显示未知。
- 身份报告第 7、36–41、65 行未把分 P、章节、镜像或静态结构夸大为新独立课程或真实播放成功。旧固定样本 4 文档/41 项观察与课程家族的边界保留。

### 取消及诊断

- `service.cancel` 取消并等待正在运行的独立任务，队列 worker 不随用户取消退出；详情子任务清理在返回确认前完成。
- `fetcher.py:375–417` 在 DNS/HTTP 路径记录取消并重新抛出取消异常；`service.py:154–178` 在任务结束保存当前任务的事件差和最近窗口。
- 生命周期报告明确网络取消回归使用隔离 `httpx.MockTransport`，并没有声称已经通过真实外站网络抓包证明“取消后零流量”。所见 README/API 也未作这种声明。任务协程清理不等于证明远端撤回已收到的请求或操作系统 DNS 工作立即物理停止。
- 诊断范围明确排除 DoH HTTP，详情条目数也未被当成真实请求次数。排队取消字段缺省见 R5。

### 新查询缓存与历史结果

- `service.py:444–488` 的 page cache key 含 `extractor_version=7`、`payload_version=2` 和解析/策略隔离；缓存载荷剥离 search evidence 及搜索回退 title/description，只保留页面/目录有凭据的相应字段。
- `service.py:641–670` 的规则匹配和 LLM 文本使用当前知识点的搜索标题/摘要，类型资格可使用全资源来源；这个区分与身份报告一致。离线回归存在同 URL 不同查询缓存及交换知识点顺序用例（`tests/test_job_lifecycle.py:334,477`）。本轮未重新执行测试。
- **历史快照边界**：`service.results():688–698` 读取已存储 match，重新计算课程身份并检查准入，不重算历史相关性。因此修复前任务中已持久化的旧匹配/摘要不会自动追溯清洗；这不是新缓存键继续复用旧包。最终报告不要声称全部历史任务均已重新排序。
- **共享展示字段边界**：同一任务中同 URL 是共享资源。若页面未提供标题/描述，卡片可显示最初发现的搜索回退文本，同时展开全部来源记录；当前评分及模型输入已按 point 隔离。它不表示每张卡片的全局展示摘要都来自当前知识点，也不表示由旧页面缓存产生。现有证据来源保留，可在解释时注明。
