## 查询与预算的具体影响

旧 `generate_queries` 始终把原知识点全文作为 stem；模型扩展词只追加到这个长 stem，而不是形成独立紧凑检索变体。每批计划 30 个逻辑查询，受 12 次搜索 HTTP 请求预算约束，实际分别到第 6 / 7 个逻辑查询。一次逻辑查询可能触发两个搜索引擎和官方发现，所以“12 次 HTTP”不等于“12 个可执行查询”。

所有点首轮均为“原点名 + 入门 视频教程”。k1 第二轮 `Python 脚本基础语法与运行 Python 脚本基础结构 课程 教学` 已记录 budget_exhausted；k6 第二轮 `pandas 分科平均分、最高分与及格率统计 分科成绩统计 课程 教学` 完成但仍主要泛候选。不能声称所有模型扩展词都获得过实际搜索验证；日志仅保存安全元数据，未保存的扩展内容 unknown。

## 最小通用修复及验收边界

1. 将已有模型给出的紧凑关键词作为独立查询变体优先尝试，仍保留原点查询与最终原点匹配；不扩大平台范围，不绕开预算，不硬编码项目名称或课程 URL。
2. 三个消费者共用中文概念边界：tokens、compound matcher、decompose；只在完整概念边界拆连词，保护“及格”“和弦”“与门”等词首。已实现并以“平均分、最高分与/和/及及格率”等组合回归。
3. 目录章节仅继承同资源、同 URL、page 字段与 source/provenance 严格对应的技术标识。继承证据同时包含目录 ID 与父字段 ID；先修文字、搜索摘要、外链、兄弟章节和冲突语言均不能提供上下文。具体教学动作不能继承；分散在不同章节的子项继续为 partial，不合成为单观察 full。已实现并回归。
4. 对同一观察已经明确的技术 + 操作 + 对象，新增受限 partial 路径；缺少的项目修饰限定必须为 unknown。该路径不能替代正常 supported，也不能用泛 Pandas、仅 API 名或跨观察拼词产生支持。具体模块由并行代理实现，本代理接线。仅在正常 whole/子项均无支持且没有 weak 结果时启用；每条观察再次去除先修句和相关课程尾部，审计规则为 `bounded_operation_partial`。
