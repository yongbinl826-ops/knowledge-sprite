# 链接发现与本机试用验收

日期：2026-10-14；项目：项目制知识引导小精灵。

此前不能用“接口已接入、离线测试通过”代替 B站、MOOC 的真实检索验收，也不应把目录缺失、播放状态和链接发现混成一个完成结论。本轮分别保留真实查询、候选、展示证据、失败和离线修复记录。

当前交付目标是给学生有来源依据的相关课程/视频链接，点击后到原平台学习。目录为可选补充；本轮不测试播放、不登录、不购买、不下载视频、不增加平台采集权限。

## 实际结论

- B站已进行真实搜索发现，有相关视频入口返回。MOOC 已进行定向搜索，但没有合格展示结果；不能称 MOOC 没有相关课程，也不能称它已成功覆盖。
- 本轮两个平台自动目录提取均为 0。代码包含目录解析能力，不等于已从这两个平台取得真实目录；此前普通浏览器可见的 B站分集也不能算应用自动提取。
- V1 冻结联网批次 8 案例、5 案例有链接，默认显示 15 项。逐项审查发现平台分栏 3 条明确串题、若干仅有泛主题证据；没有把原始命中率当准确率。
- V3 在原有 100 个持久化候选上离线重评，默认显示 14 项，仍有 5 案例返回链接；3 条明确串题消失，4 条一度被过严规则误删的相关资源恢复。没有新增外部搜索。V3 的新一轮真实搜索、独立留出泛化与未执行的 32 案例均为 **unknown**。

## 证据复核后的修复与保留代价

V1 平台分栏发现的明确误匹配：H01 的 multiprocessing managers/Queue 不是 context managers；H04 的前序/后序树遍历不是二分查找循环不变量。另 H03 的轨道尺寸与 H04 的泛二分查找课程只能支持近题，后者“Invariant First”是频道品牌，不能当作教学证据。

新规则要求英文复合知识点在同一来源观察中得到完整词面支持，允许有限复数变体。V2 过严，误删 H02 的 3 条中文相关视频和 H03 的一条准确摘要；该失败保留在 `offline-replay-v2`。V3 根据 SQL ROW_NUMBER、CSS 显式网格的官方定义增加两项有条件的技术等价，在 match.topic_match_rules 留痕，不按 URL/课程名单放行。一次中英文相邻词边界错误的 V3 试验也保留；最终 [offline-replay-v3-final](offline-replay-v3-final/summary.json) 恢复这 4 条正例并保留负例拒绝。

V3 对 100 个原始持久化候选重评，只写独立副本，源 SQLite 哈希未变。默认 14 项，默认和平台视图去重共 20 个链接；已知 3 个明确错题和 5 个近题/证据不足条目移出，新显示 1 个原已保存的 Prefab UI 应用案例。其摘要明确使用 context manager 嵌套构建界面，只能认作应用相关，不能称已确认讲授协议机制。

仍是规则系统：其他同义表达、跨语言转换、课程深度和任意知识点召回可能漏判。P@3/NDCG 不报告为人工金标准指标；这里是辅助证据审阅和开发回归。此次没有新建独立留出集，也没有为提高命中率替换联网案例。

## 本轮实现

- HTTP 200 但结果无相关课程/视频链接时，继续已允许的备用组。过滤不安全 URL、按 canonical 限制独立资源数，同时保留同 URL 不同引擎/类型的观察。官方回退不再覆盖原搜索证据，域范围和访问拒绝边界保持有效。
- 明确课程标题 + 课程根入口 + 教学摘要 + 相关性可形成搜索级课程候选；普通笔记、文档、评测列表不冒充课程。目录为空照常显示有依据的链接，课程候选不冒充视频结构已核验。
- 默认等待最多 20 项、实例每分钟接收最多 30 项，过载返回 429 和 Retry-After。幂等/进行中同请求先复用；取消释放队列，出队等待超过 300 秒即中断。清理与收尾的数据库异常不会丢队列项或击杀 worker。
- /health 检查 worker 和 SQLite，返回排队、活动任务、最近结局、来源冷却等实际状态；退化返回 503。单进程单 worker，本机 loopback 运行。
- 结果读取先使用当前准入规则，再统一生成默认/平台视图；不会因旧匹配缓存继续显示已知错题，原始记录保留。
- UI 以“前往原平台”为行动入口，目录为可选补充，取消重复的播放验收提示；来源、访问条件和未知身份仍可展开查看。

官方项目比较与两项技术规则依据见 [references.md](references.md)。没有引入 Redis、Celery、嵌入模型或新付费服务；依赖文件与本轮基线哈希相同。
