# 每点三门 MOOC 目标验收（2026-10-19）

最终按课程自己的公开大纲严格校验，三个知识点分别有 **2 / 2 / 4 门**合格课程。**每点至少 3 门的目标没有全部达到**：pandas 与 SQL 各缺 1 门，HTML 已满足目标。当前结果不能作为双平台推荐已达到生产标准的证明。

自动发现的课程与人工公开线索补库分别计数。自动来源累计发现、并在当前规则下重新取页校验后，合格数量为 **1 / 2 / 4**；人工新线索仅 CUPK 新增 1 门 pandas 完整覆盖课程。没有把人工找到的 URL 塞进自动召回测试，也没有用别名、不同学期或部分覆盖凑数。

## 验收口径

| 知识点 | 自动发现且经当前规则重验 | 人工新线索新增合格课程 | 最终库中合格课程 | 每点 3 门的剩余缺口 |
| --- | ---: | ---: | ---: | ---: |
| pandas 数据分组与聚合 | 1 | 1 | 2 | 1 |
| SQL 多表连接与分组查询 | 2 | 0 | 2 | 1 |
| HTML 表单与网页结构 | 4 | 0 | 4 | 0 |

计数按独立的数字 `course_id` 去重。同一课程的机构别名、`detail.htm?cid=` 入口或 `tid` 学期参数不会增加课程数。证据仍绑定实际课程 URL 和实际学期，不能把另一个学期、另一个入口的目录搬过来补足当前证据。

只有自身大纲完整支持所选子项，且证据来源、章节绑定、文本哈希、技术语境、有效期均通过检查，才进入主推荐。课程简介、独立教学目标、先修要求、搜索摘要和邻接章节不能单独捐赠覆盖。宽课程词命中仅允许在预算内读取课程页面，不直接获得展示资格。大纲声明覆盖不等于已验证可播放、教学深度或学习效果；没有人工金标准，precision 和 recall 均为 `unknown`。

库中存在更多有效公开课程观察，但“观察可入库”不等于“完整覆盖某个知识点”。最终预览导入 16 条当前规则有效观察，本表只计算通过三个固定知识点完整校验的 8 门不同课程。

Tavily 调用前使用只读 usage 查询验证免费计划、可用免费余额及付费使用为零。Serper 使用用户明确配置的免费试用 Key，实际余量没有独立 usage 接口佐证；执行受硬预算限制。两者都没有自动注册、购买、充值、修改账单、开启付费或切换付费备用来源。本轮没有 LLM 调用。人工公开线索的 Fetcher 复查没有调用 Tavily 或 Serper；人工搜索渠道的全局额度为 `unknown`，不混入自动 API 成绩。

## 实现变化与后台更新

- 保留实际 DTO 父子章关系 `outline_parent_index`，验证章节与父章来源、索引和整体哈希。只有真正的父章可提供该子章的技术语境，普通相邻章节、简介、先修内容不能提供这种关系。
- 增加范围明确的 HTML 文档/网页结构及 SQL 查询同义表达。匹配规则版本为 4，MOOC 提取 profile 为 15；泛化“结构”“连接”“分组”等词不会独自证明目标技术的完整覆盖。
- 搜索阶段允许有依据的技术课程探测，例如先找 Python 数据处理课程，再读取它自己的 pandas 大纲。探测资格和最终展示资格分离；查询词本身不成为证据。
- `MOOC_SEARCH_ROUNDS` 可配置范围扩大到 1–10，默认仍为 2。前 6 轮查询兼容既有观察，新增 4 轮使用所选技术和子词的有界搜索变体；不硬编码课程 URL 或课程编号。B站的查询策略不变。
- 课程族按数字 ID 去重，同时保留学期与实际 URL 的独立证据。课程库计数可能超过目标，但单次任务会按目标选择展示，不能用页面卡片数推断库中总数。
- 旧缓存按当前 profile 重新校验后才能复用；重验保留原抓取时间和到期时间，不能续期或直接给旧记录换标签。并发重验通过比较并更新（CAS）保护，较新的观察或撤销不会被旧快照覆盖。

共享课程库在后台工作，前端保持普通封面卡片，不添加“共享库命中”标签或刷新配置。SSE 保留搜索、匹配过滤、显示的增量过程；B站现有来源和功能保留。本轮 MOOC 扩量没有重新请求 B站，因此不宣称又完成了一次 B站外网可用性测试。

默认课程证据从原始抓取时间起有效 7 天。每点、每来源距最近成功真实查询满 24 小时后，由下一次用户查询触发有预算的更新；这是查询触发机制，没有无人访问时的定时抓取。失败、缓存命中或来源警告不能伪装成一次成功刷新；403、429、验证码、robots 和来源暂停继续保留停止状态。
