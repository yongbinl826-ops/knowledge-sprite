# 已确认技能如何进入推荐

项目分析的标题描述项目中的任务，`concepts` 描述需要学会的具体技能。这两者共同构成推荐目标。只传标题会丢失时间边界、数据筛选和状态转换等要求，因此本轮增加向后兼容的 `SearchRequest.learning_targets`。

- 项目确认快照逐字提供概念，按实际检索单元名绑定。每单元最多 8 条、每条最多 120 字符，每批最多 5 单元，目标 JSON 的 UTF-8 总量不超过 20,000 字节。空白、控制字符、重复、未知键和有歧义的名称碰撞明确拒绝。
- 手动检索和历史任务没有该字段时保持原有目标。空目标从规范化请求中省略，保留旧幂等键和缓存标识；非空目标参与请求身份、任务 JSON 和恢复。无需新增数据库列。
- 原任务标题、已有分解和项目限定项仍保留。追加 `learning_target_1` 等稳定 ID 与完整原文，不能只留下一个较容易找到视频的基础 API。
- 发现查询可使用尚未覆盖的概念；这只是召回，不构成来源证据，也不增加任务的请求、详情页、并发或截止时间预算。
- 每个概念单独核对同来源页面/目录的实际证据。搜索摘要、目录卡片、单元自己的概念文本、先修条件及其它工具的技能不能提供这项覆盖。来源不明确时保持未知。
- 标题完整匹配也不能自动支持未观察到的概念。所有概念均有证据也不能自动证明原项目任务和练习边界得到完整教学。
- 前端按当前单元、版本、目标 ID、原文和可见资源证据重算学习路线。历史结果漏掉的已确认概念显示为仍需补充，避免“全部覆盖”的错误暗示。

自动化与保留页面回放用于验证这条合同；真实检索的覆盖率、限制、延迟和失败案例单独记录在最终交付验收中，不能用离线通过数替代。

## 最终证据分层

媒体身份、候选相关性和学习目标覆盖分别判断。已抓网页只有search_template而无本课视频身份时转为待核对、覆盖清空；不能反向声称无视频或链接失效。来源原拼写API使用核心可单列partial，不能推断别名/参数或完成原目标，也不进入原学习路线分母；来源“本视频不教学/仅演示”同样约束该路径。

原任务有限操作核心可由真实检索标题形成partial线索；前端“本单元学习路线”采用更强的本课正文/目录门槛，不将搜索标题或本页标题直接算作已支持内容。最终CSV写出例为API some而UI0/9，原确认概念全部unknown；不得为统一数字把未通过语义判定的目录ID换成支持证据。两个口径在主验收分列，见`evidence/phase2/data-csv-source-layer-review.json`。

精确模块目标不能由泛任务同义句代替：`pygame显示文字`不证明`pygame.font 渲染文字`；明确本课模块文字或已绑定`Font/SysFont→render→blit`代码才可支持后者。只支持渲染文字，不推断游戏状态、胜利判定或项目练习完成。最终r9c独立差异闭环见`evidence/phase2/final-r9c-independent-closure.json`。
