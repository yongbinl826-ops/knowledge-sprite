## 已实现

1. **封面与搜索结果同步接收**：提取同一结果的明确缩略图字段；B站的 Serper 查询使用视频结果入口。不把整次查询的图片列表随意配给视频。Tavily 开启图片返回，但只有明确绑定的封面字段才被接受。
2. **缺失封面提前补取**：最多提前处理 4 个候选、每知识点最多 1 个，与匹配并行；复用同课程目录、限速、HTTP 与时间预算。即使新页面只有封面或抓取失败，也保留已有目录及其原观察时间。使用 pending/ready/failed 状态。
3. **整卡展示**：图片与标题一起出现；等待时显示整卡骨架，图片加载失败或超过 6 秒后保留可点击入口；新图片 URL 可在同一卡片恢复。后端 ready 只表示取得封面 URL，不表示浏览器加载或视频播放成功。
4. **请求复用与有限恢复**：模型、搜索服务使用生命周期管理的连接池，按服务、地址及凭据隔离。匹配请求仅对建立连接失败最多恢复一次，继续占用原调用额度和时间窗；读取超时、429 等不因此重复调用。
5. **查询缓存**：快速搜索使用按查询、语言、平台、来源及封面映射版本隔离的缓存。命中保留原发现时间，HTTP 请求计数为 0；当前知识点仍重新匹配。
6. **状态传输**：提供 UI 精简投影、稳定 revision、ETag/304；SSE 有界重连后回退只读 GET，保留版本隔离、心跳、后台退避和相同快照去重。
7. **数据库**：增加查询索引和版本摘要表；不变分析记录跳过重复写入，普通进度 500ms 合并，新卡、封面与终态立即保存。仅对已知可重建缓存做有限清理，保留 7 天 stale 宽限，每分钟最多清理 32 条。已有项目导入工具同步识别新增摘要表。
8. **移动端存储**：草稿 200ms 合并，提交、切换、暂停前刷新；历史版本分块、双索引提交、旧 v0/v1 副本保留。只回收两份保留索引都不再引用的旧块，提交失败不清理。大历史草稿更新不再通过桥重复读取历史块正文。
9. **实际用量诊断**：记录模型响应中的 token 用量、请求耗时、错误类型、首条推荐时间、判断比例与封面 URL 覆盖比例；服务未返回的用量保持未知，不推测费用。
10. **Tavily 备用 Key**：保存在 Git 忽略的本地 `.env`。仅主 Key 明确额度耗尽时启用备用，每次备用请求仍计入原任务预算；401/403、普通 429、网络超时不换 Key。诊断不包含 Key 原文，未额外调用付费接口验证额度。
