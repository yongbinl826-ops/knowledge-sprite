# 学习路线与推荐效用：修复前的真实对照

这里固定记录 r3 的真实结果，供后续修复回归对照。它不是最终发布验收，也不能用自动测试通过替代。当前交付与运行入口以 [交付验收](delivery-acceptance.md) 为准。

## 验收口径

先固定学生背景、原始需求和关键方法，再审查实际生成的学习路线与实际显示的课程。课程可以使用不同项目、数据、常量和示例；不同课程可分别教授一个单元的不同技能。不要求某个视频演示整个项目，也不把课程跳转能力误当成已验证播放。

重点是可练习的适中粒度、必要先修、关键算法和工具匹配、真实来源、推荐理由与未知项。泛 Python 入门不能替代 pygame 输入、碰撞、时间和状态；普通倒计时不能替代后台恢复后的真实时间准确性；原始电平边沿不能替代稳定去抖；平均行百分比不能替代总量比。

事前冻结的 [审核规则](../evidence/phase3-audit/unseen-review-plan.json) 和 [最终逐项矩阵](../evidence/phase3-audit/final-teaching-quality-matrix.r3.json) 覆盖 8 个案例、50 个单元、122 条原文技能和45个关键方法组。加权维度为学习计划25、方法适配25、材料质量25、学生适配15、迁移指导10，来源造假、明显方法过认等设独立硬门槛。未知不等于互联网没有课程。

## 学习计划的真实边界

第一次采用新技能合同的8次分析中，2例未经人工修正而独立接受，4例有可用分析但需人工修正，2例失败而没有可用计划。后续显式修复重试后，最终8份批准内容由3份自动分析和5份人工编辑组成。人工编辑没有被计为首次生成通过；重搜产生的新版本也没有被计为新模型分析。

人工发现并修正的问题包括：复习卡损坏状态恢复范围不一致、早期硬件检查依赖后面才介绍的输入/串口操作、日期API模板不一致，以及番茄钟的状态对象和渲染方法没有成为可检索技能。生成/复核提示随后增加了通用方法可追溯检查，提示改进本身不能证明下一次真实生成必然正确。

## 已证软件原因与后续回归的区分

- 来源绑定：真实2496字简介曾与截到2000字的证据不一致。修复后两者完整相等，真实重新抓取已确认；后续未知不能再归因于这个旧缺陷。
- 观察窗口：5354字本课笔记中已有 `pygame.key.get_pressed()`，旧窗口只送出开头安装说明。修复保留原字符预算、完整原文哈希和否定上下文，以通用方法标识符选择晚段。
- 候选分配：真实 Scoring 本课已有字体创建、render 和 blit，却没有进入四个审阅名额。新顺序可使用学生原确认概念中的字面标识符分配名额，并优先可审阅的本课教学笔记；这些线索绝不变成教学结论。
- 技能过认：两次模型布尔复核仍会接受泛主题。新增必要成分门将缺失的显式方法、复合步骤或限定保持未知；真实目录原题另作零覆盖贡献的章节线索。

新的门控存在保守漏召回，特别是中英跨语复合技能。真实日期代码中虽然有具体操作，不能因此声称通用语义证明已完成；同时也不能把它标成没有教学或无效链接。单方法正文可以进入原有判断/复核，显式并列、方法限定、数值、IO方向、命名空间和自身来源范围仍受检查。

修复后的真实回归单独记录，不覆盖这份失败对照；不得把重新运行直到成功的结果包装为首次成功。
