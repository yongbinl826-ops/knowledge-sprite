本文件取代旧阶段中“纯封面”“学生阶段/平台选择”“精确覆盖才显示”和“教学模式停用共享库”的说明。最终结果和证据范围见 [本轮验收](requirements-correction-20261020.md)。

输入项目名称与功能需求，偏好只选择学习语言。新项目不推断已会知识，兼容字段使用 any 与 B站/MOOC。分析生成草稿后做一次概念规范化，再返回适中粒度的专业概念供学生自行勾选；历史输入、结果与版本不会被静默改写。不要求教学任务/技能/练习表、学习先后确认或掌握度记录。

右侧按知识点显示可点击封面与真实标题。链接跳转原平台；不自动验证播放。登录、付费、地区条件不能据此认定链接无效。没有相关结果时显示明确空态与重试，旧结果保持可回看。标题、简介或真实目录支持的相关视频允许显示，但不声称已经精确讲授全部内容、完整覆盖项目，或编造章节/时间戳。

## 自动发现与后台复用

默认 PARALLEL_PLATFORM_SEARCH=true、OPEN_WEB_SEARCH_ENABLED=true。每个选点先获得不限域的全网发现、B站和MOOC各一轮机会，平台lane并行。全体首轮完成后才进行补搜；查询、详情、并发、任务时限和成本受既有硬上限约束。预算容不下首轮时在提交前明确拒绝，不能暗中超限或让早期点的补搜挤占后续点。旧持久化查询计划按原版本恢复，不添加未预留请求。

单批补搜计划超过该批请求上限时，按点和来源均衡裁剪可选补轮，保留完整首轮。项目还受总批次、总请求、详情和时限预留上限约束；整体选择超额会明确拒绝，保留选择与需求，不偷偷丢弃知识点。

教学匹配与后台共享复用、缺口补搜、查询触发刷新可同时工作。复用的公开课程事实必须重新核对当前知识点；相关参考不计入严格完整目录覆盖。刷新是实际查询时的有界动作，不是无人使用时定时联网；失败和缓存命中不伪造成功观察。来源拒绝、验证码、限流和冷却继续生效，不能换身份或路径绕过。

手机正常新任务可读取持久化公开课程事实，私人项目、需求、查询词、选择和笔记不能写入共享事实库。共享库没有前端入口，也没有匿名修改课程记录的接口。手机任务私有运行状态仍在RAM，项目与历史仍保留在本机存储。

## 分析与概念边界

生成提示为 project-analysis-v5.17-thorough-concept-normalization。新知识点只含名称、简短说明与必要的技术背景；说明写清学什么、服务哪项需求。系统仅补内部 ID 和勾选状态。模型不再生成前置关系、学习顺序、功能图、任务拆解或掌握度画像；列表展示、确认和新检索按返回数组顺序，真正必要的基础概念作为普通知识点列出。原有历史字段和已确认快照仍可读取，不改写已有记录。

数量由完整实现需求所需的独立概念决定，不设期望条数，不因描述短而压缩。按原始需求、明确约束和所选技术方案核查必要环节；区分格式校验与内容符合性，在相关概念说明中覆盖必要的完整性、一致性、数值或规则检查。不能凭格式正确就宣称满足需求，也不能用猜测、空值或默认值代替必需信息。未给出的权威规则或输入材料应明确为待提供条件，不从常见惯例推定符合要求。

同一机制的紧密相关方面可以合并，具有独立原理和学习内容的机制应分开；共用框架、界面、功能或开发阶段不是合并依据。跨功能复用同一概念，不按变量、API、参数或操作步骤拆分，不为凑数或压缩条数改变粒度。核查维度仅在相关时适用，不向所有项目强加固定主题。24 个知识点仍是安全上限，确实容纳不下时明确提示分阶段分析，不能删减必要内容。

正常分析使用两次模型调用：第一次生成草稿，第二次结合原始需求与草稿规范化重复、名称、机制覆盖及方法与保证的一致性，返回完整的相同格式。首轮若未通过校验，第二次同时承担修复和规范化；不增加第三次调用，仍共用原有总时限。第二次失败时不能用未经规范化的第一稿冒充最终结果。运行能力中 `concept_normalization_enabled=true`、`normalization_max_calls=1` 明确标示此阶段，旧评分评审器仍停用。两阶段与本地检查也不等于所有项目的语义完整性认证，仍需真实内容验收。

第二轮使用独立的规范化提示，先从原始需求重建必要机制，再与草稿对照查漏；不沿用草稿分点逐条润色。可以删去无需求依据的兼容范围、交互模式或优化功能，但不能因此漏掉原始需求。两轮都只生成相同的简明知识点格式。

同一声明式机制的定义与应用通常合成一个完整学习目标，不能仅因发生在前后阶段拆点；若实际学习解析器或执行引擎的独立内部算法，则另行表达。

完整覆盖优先于去重和删减。模型内部逐项核对草稿保留、归并或删除的去向；只有原始需求不需要且最终方案也不再使用时才可删除。归并保留全部必要用途，最后再次从所选方案反查知识点，防止首稿原本就漏项。提示词、响应格式、表单控件等相关知识不能吞掉真正独立的接口使用、跨交互状态等机制。名称中“专业机制 + 本项目用途”的用途部分移入说明。同一核对机制服务多个输入、约束或输出对象时，保留每个必要用途而不重复拆点。这是生成行为约束，不是服务端已证明任意项目覆盖完整。

在已识别的官方 DeepSeek 接口上，只有 thinking/effort 同为 auto 时，第二轮自动使用 enabled/high 进行概念重组；第一轮和共享检索调用保持原有设置。显式禁用、显式强度和未知兼容网关不被覆盖。第二轮使用独立配置 `PROJECT_ANALYSIS_NORMALIZATION_MAX_OUTPUT_TOKENS`，默认 12000、有效范围 256–16000，供推理和完整 JSON 共用；第一轮仍使用 `LLM_MAX_OUTPUT_TOKENS`（默认 6000），总时限和两次调用上限不变。此修复来自 v15 实际第二轮在 6000 额度下被截断的记录，不能把第一稿或不完整响应当成成功。能力接口公开本阶段实际选用的模式、强度与额度。参数依据为 [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)，JSON 输出继续使用既有格式和截断检测，见 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

先说明可迁移的原理、表示或操作，再说明其全部项目用途；“保证完整、确保正确”是目标，不能代替所学机制。比较概念时把业务对象、字段和阶段替换为中性对象：若剩下的原理和操作相同，就归为一个概念并保留所有用途；若原理不同，即使都用于校验也分别保留。名称从实际学习机制选取规范专业术语，不能给业务任务加上“处理、管理、校验”就当作知识点，也不能只删除业务词而不补清机制。提示词用跨领域对照解释判断方法，不提供项目专用必选清单。

同一校验机制应用于不同业务字段时，具体规则保留在说明中，不各拆成一条。所选方案涉及界面时，同时核查输入交互与跨交互状态，不能互相替代。输入过长时应保留全部必要内容分块、合并核对，或明确说明无法处理，不能通过截断、抽样或静默丢弃完成任务。语言与检索平台等应用配置不作为被分析项目的功能要求。

名称不再仅凭“与／、／以及／and”、连接两侧长度或中文动词开头被拒绝；专业名词中的“创建、让、使”等片段不能独自作为任务句证据。明确的祈使、指示对象、目的句、步骤标签、任务串联、单行语法及整门学科名称仍会反馈修正。同一机制的相关方面可以保留在一起，独立机制仍由通用提示词要求分别表达。这不代表任意含连接词的名称都已通过语义认证。

新增生成校验只在显式技术背景相同、名称仅相差该技术前缀时报告字面重复，例如同属 Python 的“Python 列表索引”和“列表索引”。保留 C++、.NET 等有效符号；单字符技术标识可能属于术语自身，不自动剥离。检查不按说明相似度或“校验”等词尾推断重复。反馈标明重复双方，要求核查机制后归并用途，真正不同的机制应使用可区分的专业名称；不在服务端静默删点或合并。此检查不修改历史读取及用户编辑记录，业务表述不同但机制相同的语义去重仍需结合真实生成结果检查。

生成被拒绝后，完整且未含配置密钥的 JSON 候选立即记录在该项目版本的 `rejected_analysis_attempts`，附尝试序号、原因、坐标、时间、模型和提示词版本，修正成功或重启后仍可追查。该字段可从本项目版本 API 读取，是不可信审计数据，不作为已通过分析、知识点或共享课程事实。错误提示仍只带摘要；无完整 JSON、含配置密钥或超出审计大小上限的响应只记录缺失原因。旧版未记录的正文不能追溯恢复。手机端使用原有 RAM 私有任务存储，不写入共享库。

`analysis_attempts` 同时记录两轮原始响应及 draft、accepted、rejected 状态。第一稿通过本地校验后、开始规范化之前即存档；中断不会让它进入可用分析。最终仅返回第二轮通过检查的结果，模型未返回完整响应时如实记录缺失，不补造正文。审计仅属于当前项目版本，不参与课程匹配或共享库复用。

## 本地运行、健康与回滚

原工程：D:\项目制知识引导小精灵；仓库：yongbinl826-ops/knowledge-sprite。使用已有环境：

```powershell
cd D:\项目制知识引导小精灵
.\scripts\start.ps1 -SkipInstall -NoBuild
```

常用启动器默认仍为8000、单worker和本机回环地址；上述两个现有参数跳过依赖安装及Web重建。启动器自动为未明确指定的全网、平台并行、教学匹配、后台共享库、缺口补搜和查询触发更新六个开关提供true，旧.env不会在常规启动时将它们关闭，无需手动逐项设置。进程中显式设置的false保留；脚本退出或启动失败后恢复调用者原环境。直接自定义uvicorn或服务管理器入口仍尊重其显式配置；运行时解析在无配置时默认启用这六项。两份非敏感部署示例保持相同默认，来源、密钥、权限、预算及其他安全关闭项不变。

普通网页使用 frontend 的既有 Node 环境执行 npm run build；未进行APK构建、安装或发布。现有服务已启动时不要重复执行启动命令。当前实际预览仍为 http://127.0.0.1:8928（手机API8017），网页为 http://127.0.0.1:8001。2026-10-21 的知识点格式修复已构建网页与手机预览资源，并在确认空闲、备份数据库后重启这两个 API；进程身份以该次重启记录为准。配置及凭据保持原值。/health/live、/health、/health/ready 分别检查进程、队列、配置及最近观察；ready 不等于第三方当前可用。

本轮只以哈希比较并交换明确的公共文件，并先备份原文件；发现并发改动停止覆盖。回滚只恢复本轮已核对的公共源码和网页资产，不恢复测试数据库、不覆盖更新后的学生数据。生产公开部署仍需要另行授权、稳定来源验证、认证/TLS、容量与恢复演练。没有新建凭据、购买接口、推送Git或部署外网。
