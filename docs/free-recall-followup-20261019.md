## 最终实现

1. MOOC 查询先保留原精确首查，在既定首 6 个名额中优先安排已经规划的不同显式子短语，减少只换尾缀的重复。总查询多重集、后 4 个可选名额和预算均未扩大；不从旧技能字段猜技术栈，不按课程 ID 硬编码。查询策略缓存版本升为 v3，精确回读 v2／v1 的同一查询和原 TTL，不续期、不洗成新缓存，refresh 仍绕过。
2. 已成功抓取的视频，其教学判断必须来自绑定同一资源／页面 URL 的自身标量证据，搜索标题／摘要只保留作发现和审计。补上 provenance URL、来源、文本、证据 ID 一致性检查；没有扩张视频身份白名单或把较弱身份断言升级为较强断言。
3. 标准 API 与专业知识点的映射受上下文约束：JSON.stringify 仅支持明确 JavaScript／浏览器存储语境中的 JSON 序列化子主题，不能据此证明存储 IO。按钮知识点同样要求同一自身内容明确出现按钮、消抖和按下／释放检测，不推断具体算法。
4. 处理同一句的否定、被动／缩写、以后才讲、其他课、对比材料和相邻无关内容；修复真实 CSV 标题／正文边界回归。学生阶段适配也使用视频自己的标题／简介，防止搜索尾词污染。推荐理由准确区分自身标题、简介和目录，算法深度及播放未知不会补写成已证实。
5. 前端把已有后端子主题及真实卡片证据摘要放在左侧，明确“已有依据：JSON 序列化”“待补依据：读写”。右侧仍仅展示封面。聚合声明、外来资源／证据 ID、待核卡片或不安全 URL 都不能单独供给显示支持。封面键盘焦点改为绘制在图片上方的可见蓝色内环，适配减少动态效果偏好。

API 标准语义可对照 [MDN JSON.stringify 文档](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify)：将 JavaScript 值转换为 JSON 字符串，不能替代 localStorage 的读写证明。

```powershell
Set-Location -LiteralPath 'D:\项目制知识引导小精灵'
& '.\.venv\Scripts\python.exe' -X utf8 -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8001 --workers 1 --no-access-log
```

健康检查为 `/health` 和 `/health/ready`。ready 的上游判断明确是配置和最近观察，不等于第三方即时可用。依赖、构建、持久化／迁移、安全／隐私及部署前置条件沿用项目 `README.md` 和 `docs/production-readiness.md`；本轮没有强加新基础设施。原有 `.env` 字节保持不变，`TEACHING_MATCH_ENABLED=true`，专业知识点模式和关闭 critic 保持，未推送 Git、未部署外网。

每次应用前先核对来源哈希、原文件哈希、Git HEAD、受保护配置和数据库内容；回滚副本仅在命名的本机 Windows Temp 目录，准备回执记录其位置，交付包排除。后端更新只停止已验证的空闲 8001 自有 uvicorn；第一次时间戳格式守卫误报时未停止或写文件，修正 UTC 比较后才继续。前端新产物先发布不可变资源，最后原子切换 index，保留旧资源；不需要重启服务。回滚代码前须核对本轮 after 哈希，不能覆盖之后的用户修改，更不能把旧数据库恢复到新学生数据上。8002 单独预览保持不动。
